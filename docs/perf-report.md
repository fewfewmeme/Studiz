# Reader performance report (Round 10, section 00)

**Method.** Chromium (Playwright) with an iPad context: 1180×820 @2x, mobile, touch, iPad user agent, **4× CPU throttling** (CDP). Swipes are real touch events through the browser's input pipeline (`Input.dispatchTouchEvent`), not synthetic JS events.
Test file: `tests/fixtures/perf/angiology162.html` (generated by `node tests/gen-perf-fixtures.cjs`, 458 KB of text, headings, 13 tables, 27 pictures; 158–162 Книга pages) and a 162-page scanned-style PDF (`scan162.pdf`).
Scripts: `tests/perf-measure.cjs` (the same script produced "before" and "after"), `tests/reader-perf.spec.mjs`, `tests/reader-layout.spec.mjs` (`node --test`).

> **Not verified on a real iPad / WebKit.** WebKit cannot be downloaded in this sandbox (the download host is blocked), so everything was run in Chromium. The causes below were found by measurement in Chromium; each is also a bad pattern in WebKit, but the exact iPad numbers must be checked on the device. Please test on the iPad and tell me if anything still stutters.

## Root causes (all reproduced and measured)

| # | Cause | Where | Evidence |
|---|---|---|---|
| 1 | **A horizontal swipe in Книга was claimed by the browser.** The page inside the frame declared `touch-action: pan-x pan-y`, so a swipe ended in `pointercancel`; the page-turn code listened only for `pointerup`. A turn happened only when the browser happened not to take the gesture: "5 to 100 swipes". | `js/frame/rt/75-pinch.js:7`, `js/frame/rt/70-book.js` (old `pointerup`-only handler) | before: **0 of 20** and **0 of 50** swipes turned the page (20 `pointercancel`, 0 `pointerup`) |
| 2 | **`content-visibility:auto; contain-intrinsic-size:auto 700px` on every top-level block of any document over 250 000 characters.** Every unseen paragraph became a 700 px placeholder. In Книга one paragraph filled a whole page (the 158-page flow became **634 pages**, a **417 397 px** wide strip); in Обычный the scroll height jumped while reading ("everything flies away"). The file triggers it every time, which is why a reload never helped. | `js/frame/rt/90-boot.js:34` (old) | before: Книга 634 pages instead of 158; Обычный `scrollHeight` 307 130 → 223 700…303 870 while scrolling |
| 3 | **Page-turn animation re-layerized the whole strip.** A CSS transition / Web Animation / `will-change` toggle on the 80 000 px column strip makes the browser rebuild the layer tree for every paint chunk of the document: ~2.1 s per turn at 4× CPU (Chromium trace: `Layerize` 4 167 ms of one frame; hiding the paragraphs made it 17 ms). Any repaint inside the frame (page numerals, shade animation) costs the same. | `js/frame/rt/70-book.js` `show()`, `body{will-change}`, `.lz-shade` animation, `overlay()` during the turn | intermediate build (swipes fixed, old animation): 2 083–2 200 ms per frame; 4 s task for one turn |
| 4 | **Sizing the reader from `visualViewport.height`.** When Safari's page zoom is above 1 (it is remembered per page across reloads) the visual viewport is smaller than the layout viewport: the reader was shortened (empty strip under the controls) while the spread was laid out for the full width (right page cut by the screen edge). | `js/reader/reader.js` `fitViewport()` (old) | emulated page scale 1.6: reader height = 512 px on an 820 px screen |
| 5 | Persisted view state was trusted (zoom per mode, reading position, edits). A broken value survives a reload. | `js/reader/framedoc.js` `load()` | now validated and clamped (`js/viewstate.js`) |

## Fixes

1. **Swipe**: Pointer Events with a single gesture owner (threshold 8 px, turn if |dx| > 40 px or velocity > 0.3 px/ms), `touch-action: pan-y` on the page in Книга, `pointercancel` finishes the gesture instead of dropping it, a second finger cancels (pinch), `isTurning` lock that remembers **one** next turn. (Deviation: no explicit `setPointerCapture` — touch pointers are captured implicitly, and capture would retarget `click` away from marks and links.)
2. **Long documents**: `content-visibility` is no longer used in Книга; in Обычный it is applied only after the true height of every block was measured once (`contain-intrinsic-size: auto <measured>px`), so the scroll height is stable. (`js/frame/rt/20-layout.js` `cvApply()`.)
3. **Turn animation**: a short `requestAnimationFrame` loop with a 2D `translate` (measured 76 ms of CPU per turn at 4× against 2 100 ms for a transition / Web Animation). No `will-change`, no CSS transition, no shade animation on the strip. Page numerals and running head change **after** the slide, once. Anchor reporting (`caretRangeFromPoint`) runs 500 ms after the last turn, in an idle callback (`setTimeout` fallback); pictures of the next two spreads are decoded in idle time from a per-layout column table instead of measuring every `<img>` on each turn. Persisting the position: at most once a second and on `pagehide`.
   *Note on "`will-change` only during the animation":* for this one strip the opposite is true (toggling it re-layerizes the strip), so it is not used at all; the legacy PDF leaf (`book.js`) gets `will-change` only while it turns.
4. **Viewport**: `.reader` is `position:fixed; top/right/bottom/left:0` (no `100vh`, no JS height), landscape insets include `env(safe-area-inset-*)`, the pager sits above `safe-area-inset-bottom`; `js/viewport.js` undoes Safari page zoom (re-applies the viewport meta with scale locked to 1) at boot, on `visualViewport` resize and `pageshow`; `orientationchange` re-lays out. `html.reader-open` locks scrolling **only while the reader is open** and is removed in the cleanup (`finally`) and at boot.
5. **State**: `js/viewstate.js` validates zoom, width, weight, family, position, block edits; `Настройки → «Сбросить вид читалки»` clears only view keys (`fz:`, `fpos:`, `pos:`) and the `konspekty-*` caches; files, marks, bookmarks, receipts are untouched.
6. **Service worker**: only complete `200` same-origin responses are cached (never `206`/opaque); old `konspekty-*` caches are deleted on `activate` (already so); cache name = build hash (`tools/build-sw.mjs`). The update stays "waiting" until «Обновить» (deliberately not `skipWaiting` mid-reading).

## Open / close retention (20 cycles, after a forced GC, `Memory.getDOMCounters`) — RESOLVED

| per open + close | before round 10 | round 10 (measured with undisposed Playwright handles) | now (handles disposed) |
|---|---|---|---|
| DOM nodes retained | ~425 | ~193 | **0.0** |
| JS event listeners retained | ~69 | 10 | **0.0** |
| documents | 1 | 1 | 1 |

**The residual was a measurement artefact, not an app leak.** `node tools/heap-retainers.cjs` takes a heap snapshot after N cycles and prints the shortest retaining path: every detached `<iframe class="lz-frame">` was held by `(GC roots) → (Global handles) → "DevTools console"`, i.e. by the `ElementHandle` returned by Playwright's `page.waitForSelector(...)` (never disposed), which pins the iframe and the home cards. With `.then(h => h.dispose())` the same 20 cycles leave 699 → 699 nodes and 91 → 91 listeners (reproduced both ways: 193.0 / 10.0 with leaking handles, 0.0 / 0.0 disposed). `tests/reader-perf.spec.mjs` now disposes the handles and guards ≤ 5 nodes / ≤ 1 listener per cycle. Still measured in Chromium only; the iPad numbers are not collected yet.

## Legacy block engine
`js/reader/blocks.js` (own timer, own storage) is reachable only through `pdfdoc.js`, i.e. old PDFs/images stored without conversion. «Блоки» is now hidden for them (`PdfDoc.noBlocks`); all converted files use the single study timer (`js/study-store.js`).
